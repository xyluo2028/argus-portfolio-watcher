1. Goals & non-goals

Goals

  • Build and track your own portfolios from a trade log (multiple portfolios + a watchlist).
  • Near real-time prices on trading days, with live P&L, day change and weights.
  • Charts: candlesticks with indicators, plus portfolio performance vs a benchmark (SPY/QQQ).
  • Valuation & fundamentals: PE, forward PE, PB, PS, EV/EBITDA, revenue & growth, margins and more.
  • Agent-first: every feature is reachable from an MCP server and a JSON CLI, not only the UI.
  • Local-first on your Mac, free data to start, with a pluggable data-provider layer.

Non-goals (for now)

  • Placing real brokerage orders.
  • Non-US markets, options, crypto, FX and bonds. The schema leaves room for them; v1 doesn't implement them.
  • Multi-user accounts, auth and hosting.
  • Notifications (macOS or push), paid or premium data (analyst ratings, price targets, smart scores), and non-English UI.
  • Rebuilding your complex research routines in the app. The app serves data to them through MCP, and Claude does the reasoning.
  • Tick-level, exchange-grade real-time data. Free feeds give you "live enough".

Everything runs on your Mac. SQLite in WAL mode lets the web server and a separately spawned MCP stdio process share one database safely.
How the MCP server runs. argus serve starts the API, the UI, the scheduler and an HTTP MCP endpoint at /mcp. argus mcp is a stdio entry point for Claude Desktop that imports the same core and reads and writes the same database. If the live server isn't running, it fetches quotes on demand and caches them. So agents keep working whether or not the app is open.

6. Data model

7. Metrics & analytics

Position / portfolio

  • Market value, weight
  • Unrealized P&L ($/%)
  • Day P&L ($/%)
  • Realized P&L (FIFO)
  • Dividends received
  • Allocation by sector and by position

Valuation / fundamentals

  • PE (TTM), forward PE, PEG
  • PB, PS, EV/EBITDA
  • Market cap, dividend yield, beta
  • Revenue TTM, YoY growth
  • Gross, operating and net margin
  • EPS, FCF, ROE, debt/equity
  • 52-week range and position within it

Technical (computed locally)

  • SMA/EMA 20, 50, 200
  • RSI(14), MACD(12,26,9)
  • Bollinger(20,2), ATR(14)
  • Average volume, relative volume
  • Drawdown from high

A small numpy/pandas module. It avoids a dependency on unmaintained technical-analysis libraries.

Performance vs benchmark

Portfolios hold positions only, with no cash. Market value Vt = Σ qtyt · closet is rebuilt from the trade log and daily bars. The daily return is rt = (Vt + Dt − Ft) / Vt−1 − 1, where Ft is buy cost minus sell proceeds that day, and Dt is dividends. Chaining these daily returns gives the time-weighted return (TWR), so adding money doesn't count as performance. OPENING lots enter as a flow at that day's closing market value, not at their original cost. That way a stock bought years ago at a much lower price doesn't show up as a one-day gain on the import date. Cost basis and unrealized P&L still use the original price. History starts at the earliest opening date. The benchmark (SPY by default, set per portfolio) is normalized to the same start date. Also reported: total return, CAGR, max drawdown, volatility and Sharpe (risk-free rate from the 3-month T-bill).

9. Agent / MCP design

Design rules that make this easy for agents to operate:

  • Few, coarse tools that accept lists, e.g. get_quotes(["NVDA","MSFT"]), so a question needs one call, not N.
  • A fields parameter to return only the metrics asked for, which keeps responses small.
  • Freshness on every value: as_of, source, delayed, market_session.
  • Safe writes: dry_run by default in the tool description, idempotency_key so a retry can't double-book a trade, soft delete, and an audit log entry with actor=mcp.
  • Clear errors, e.g. {code:"UNKNOWN_SYMBOL", hint:"did you mean GOOGL?"}.
  • The CLI mirrors the MCP tools (argus quotes NVDA MSFT --json), so Claude Code can use either.

12a. Investing.com importer spec

The file is UTF-8 with a BOM and contains several sections, each starting with a title row. Argus reads only these fields and ignores everything else: live prices, P&L, weights, earnings dates, market cap, technical signals and so on. Argus fetches all of that itself.

Section · columnArgus fieldParsing
"Open Positions" · SymbolsymbolStrip Reuters suffixes .O (NASDAQ) and .K/.N (NYSE). Bare symbols are kept as-is. Each symbol is checked with Finnhub before import.
· Name, Exchangeinstrument.name, exchangeOnly used to create the instrument record if it's missing
· Open DatetsMM/DD/YYYY, treated as the market close in New York time
· Typemust be BUYAny other value (a short position) is rejected
· Amount, Open Price, Commissionqty, price, feeRemove $ and , characters
"Open Positions Summary" · Amount, Avg Pricenot storedCheck only: share count and average price per symbol must match the lots
Totals · "Market Value", "Open P/L"not storedCheck only: total lot cost must equal market value minus open P/L, within $0.05
File name <portfolio>_Holdings_MMDDYYYY.csvportfolio.nameCan be overridden with --portfolio

OPENING vs BUY: lots dated on or before --opening-through (a date you pass on the command line) become OPENING; later ones become BUY. The --dry-run preview shows each lot's type and the check results before anything is written. Re-running the same file is safe: each lot gets an ID made from its symbol, date, quantity and price, so it can't be imported twice.

13. Risks & mitigations

RiskMitigation
yfinance breaks or gets rate-limited (it's unofficial)Fallback order per data type, cache everything, batch requests, back off on errors, and show "stale" in the UI instead of failing. A paid adapter can replace it later.
Different sources give different fundamentals (e.g. PE definitions differ)Store source with each metric, document definitions in the UI tooltip, and prefer EDGAR for statement data.
Imported lots are only open lots. Sells made before the import aren't in the export.Realized P&L starts at zero on the import date. Performance is measured from the opening dates onward, not before.
Corporate actions (splits, ticker changes) corrupt cost basisA SPLIT transaction type plus split detection from provider data that prompts you to confirm.
An agent books a wrong tradeDry-run preview, idempotency keys, soft delete and an audit log. The UI shows a badge on agent-entered trades.
Free-tier limits with a large watchlistOnly stream held and watched symbols (fine up to about 50 for Finnhub free). Everything else is fetched on demand.
